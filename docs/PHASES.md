# Build history and open work

## Where the project came from

NewsSparkle was exported from Lovable and developed in two documented phases,
both of which are preserved in the repository root:

| File | Scope |
| --- | --- |
| `AUTHOR_AVATARS_IMPLEMENTATION.md` | Cropping the six desk avatars from `src/assets/export.png` |
| `IMPLEMENTATION_CHECKLIST.md` | Phase checklist for that work |
| `FINAL_MANIFEST.md` | Completion manifest for that work |
| `AVATAR_SUMMARY.sh`, `crop_authors.py` | The scripts that produced `public/authors/*` |

Those documents are kept as history. Two of their claims do not match the code
they describe, and were corrected in this phase:

* They state *"TypeScript Check: ✅ ZERO ERRORS"* — `tsc` reported six errors,
  one of which (`AuthorImage is not defined` in `PostPage.tsx`) blanked every
  article page in production.
* They describe `/logo.svg`-era wiring that no longer matched the assets on
  disk.

## This phase — audit and remediation

Full findings: [`../REPO_ANALYSIS.md`](../REPO_ANALYSIS.md).

### P0 — broken in production

- [x] **Article pages crashed** (`ReferenceError: AuthorImage is not defined`
      in `PostPage.tsx`) — the import was missing, the build never type-checked.
- [x] **Every avatar rendered broken** — `OptimizedImage` advertised
      `<source type="image/webp">` for `.webp` files that did not exist, and
      browsers do not fall back to the `<img>` when the source 404s.
- [x] **Missing assets** — `/logo.svg` (notifications, brand config) and
      `/og-default.jpg` (the default social card for every page, which was a
      Lovable preview screenshot hosted on an R2 bucket).
- [x] **Featured images** came from `source.unsplash.com`, retired by Unsplash.

### P1 — security, correctness, revenue risk

- [x] **Anyone with the public anon key could rewrite published articles.**
      The old "views only" policy added a column grant without revoking the
      table-wide one, and its RLS predicate was row-scoped. Now: `REVOKE ALL`
      plus `GRANT SELECT` on editorial tables, and the counter goes through a
      `SECURITY DEFINER` RPC.
- [x] **Unauthenticated automation endpoints.** `auto-publish` accepted any POST
      (outbound API calls + LLM spend + DB write); `notifications-dispatcher`
      could be spammed into pushing fake breaking alerts. All write-capable
      functions now require a shared secret.
- [x] **Cron pointed at a different Supabase project** and embedded a
      long-lived key. Jobs now target the configured project and read the secret
      from Vault; the monitor and dispatcher are scheduled too.
- [x] **`{count:5}` was ignored** (the handler only read `category`/`slot`), so
      the "18 posts/day" plan produced ~6. Slots now fan out across six
      categories: 3 × 6.
- [x] **Fabricated `aggregateRating`** derived from pageviews removed from
      article JSON-LD.
- [x] **Sitemap and robots.txt pointed at the front-end host**, where the feed
      functions do not exist. Both are now generated by `npm run seo` with the
      real `*.supabase.co` URLs.
- [x] **No type-check in the build, no CI.** `npm run build` runs `tsc` first,
      `npm run verify` runs the full gate, and `.github/workflows/ci.yml` runs
      it on every pull request. The npm-publish workflow (which would have
      failed on a private, unpublished app) was removed.

### P2 — quality and maintainability

- [x] View counting is de-duplicated per reader per day (`post_view_events`)
      and rate-limited by construction; the counter is no longer inflatable.
- [x] Queries select explicit columns instead of `select("*")` for cards,
      rails and pagination (article bodies are fetched only by the article page).
- [x] Homepage category blocks load in parallel rather than in a sequential
      loop; every page now surfaces load errors instead of rendering "no news".
- [x] Route-level code splitting works again — `manualChunks` no longer forces
      every page into one shared chunk.
- [x] `LanguageToggle`: fixed a stateful global regex that skipped every other
      text node, and an ESLint-clean Devanagari character class.
- [x] Error boundaries at the app root, keyed by route.
- [x] "Continue reading" actually works now (the article page records the last
      read slug that the rail was already looking up).
- [x] Source pipeline: live RSS endpoints (the old Reuters feeds were retired),
      timeouts on every outbound request, duplicate-headline rejection,
      hallucinated internal links stripped, reading time computed from the body.
- [x] Dependencies cut from 55 to 25 runtime packages; 33 unused `ui/*`
      components, the dead `components/home/*` set and two unused components
      removed.
- [x] Brand assets rebuilt: 836 KB logo → 106 KB, real icons
      (`icon-32/48/180/192/512`, `apple-touch-icon`), a proper 1200×630 OG card,
      and 24 author WebP twins (141 KB PNG → 12.7 KB WebP each).
- [x] Deploy size: `dist/` 7.3 MB → 3.1 MB (avatars normalised from
      600 px PNGs to their 72–320 px display sizes + WebP twins; CI fails the
      build above 4 MiB).
- [x] Demo mode (`npm run dev:demo`) renders the whole site from local fixtures
      with a loud "sample data" banner, so the UI can be previewed without a
      database.
- [x] Tests: 52 across article rendering, homepage rendering against the demo
      data layer, error boundary, data normalisation, site/author contracts,
      asset integrity, edge-function auth, migration hygiene and build config.
- [x] Docs: this file, `OPERATIONS.md`, a real `README.md`, `.env.example`.

## Phase 6 — Full autonomous newsroom (complete)

The site now runs its own newsroom: it ingests, writes, checks, schedules,
publishes, watches trends, repairs itself and reports. Read
`phase6_summary.txt` for the short version and `docs/OPERATIONS.md` §3 for the
schedule.

- [x] Data model: `content_sources`, `ingested_items`, `topic_trends`,
      `pipeline_runs`, `agent_alerts`, `content_health_checks`, plus scheduling,
      provenance and quality columns on `posts` (one migration, one rollback
      story).
- [x] Ingestion: 24 seeded trusted feeds (wire/outlet/specialist tiers), RSS +
      Atom parsing, validation (furniture, sponsored, clickbait, non-English,
      stale, future-dated, listing pages), cross-source deduplication with
      corroboration counting and exponential feed cooldowns.
- [x] Writing: source → extraction → rewrite → verification → SEO → quality
      score → candidate, with the writer and verifier both constrained to the
      supplied source material.
- [x] Category assignment with confidence, source-hint fallback and
      misclassification detection.
- [x] SEO generation (slug, meta title/description, OG/JSON-LD fields, keywords)
      with validation and de-hyping of model copy.
- [x] Featured images: Unsplash → Pexels → deterministic placeholder, WebP
      requests, credit lines and alt text.
- [x] Quality scoring (0–100) with publish/review/reject thresholds and hard
      blocks for unsafe, plagiarised, duplicate, truncated or unverifiable copy.
- [x] Duplicate detection: fingerprint, title similarity, 4-gram shingle
      overlap and a simhash prefilter for the archive.
- [x] Scheduling: edition windows, category balance, per-run burst limit, daily
      and per-category caps, minimum gap, catch-up without flooding.
- [x] Failure recovery: bounded retries, circuit breakers, timeouts, feed
      cooldowns, candidate retry/defer, alerts, and "stop rather than invent"
      when the AI is unavailable or the budget is spent.
- [x] Trend detection and content gaps that reprioritise the queue but never
      generate a story on their own.
- [x] Maintenance: image repair, stale/archived content, outbound link checks,
      endpoint freshness, orphan detection, internal-link suggestions.
- [x] Safety gates: safety scan, defamation-risk escalation, plagiarism run
      length, figure grounding, attribution, explicit no-fabrication prompts.
- [x] Resource efficiency: per-day LLM budget, per-run caps, telemetry on every
      run, retention pruning.
- [x] Verification: `npm run verify` green; 165 tests including end-to-end
      pipeline runs against an in-memory database and recorded AI responses.

## Open work

Ordered by impact. Nothing here blocks the site from running.

1. **Pre-render article routes.** The site is still a client-rendered SPA, so
   social unfurlers see the generic OG card. Options: run
   `vite-plugin-prerender`-style snapshots at publish time, or move the public
   routes to SSR (Next/Remix/SvelteKit). This is the single biggest remaining
   SEO win.
2. **RSS/Atom validation in CI.** `validate-feeds` covers the deployed feeds; a
   `w3c`-style XSD validation of sample output would catch regressions earlier.
3. **Image pipeline for article heroes.** Unsplash/Pexels keys make images
   topic-relevant; without them the fallback is a seeded random photo. Consider
   generating a branded card per article at publish time.
4. **Review queue UI.** Phase 6 writes anything uncertain into `posts` with
   `status = 'review'` and a `review_reason`, but there is no screen for it yet:
   a reviewer currently reads those rows in SQL. A one-screen approval view
   (approve → `scheduled`, reject → `archived`) is the next editorial win.
5. **Category source of truth.** `src/lib/site.ts` and the `categories` table
   both define sections; the database should drive the front end. The stray
   `world` and `sports` rows from the first migration are still in the database
   and still listed by `/search` and the dynamic sitemap.
6. **Accessibility pass.** Language switching does not update `<html lang>`;
   `BookmarkButton` is an interactive `<button>` inside a `<Link>`; contrast on
   `--byline` should be measured against WCAG AA.
7. **Observability.** `phase6-monitor` (cron `5,35 * * * *`) plus
   `pipeline_runs`, `agent_alerts` and `content_health_checks` now cover
   silent-failure detection. Still missing: an outbound notification when a
   `critical` alert opens (email/Slack), and a weekly digest.
8. **Retire `src/assets/export.png` (24 MB).** It is the source for the avatar
   crops and is kept for provenance; move it to external storage and reference
   it from `crop_authors.py` when that is no longer needed.
